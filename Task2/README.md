# Задание 2

DFD: `dfd.png` (исходник `dfd.puml`).

## Домены

| Домен | Что внутри | Почему отдельный |
|---|---|---|
| Клиники | Приём, лечение, медкарты, исследования, счета на лечение | Ядро бизнеса. Медданные под врачебной тайной и 152-ФЗ |
| ИИ | Модели, датасеты, рекомендации врачам | Отдельная компания, свой цикл релизов моделей. Работает с медданными по изолированному контуру |
| Финтех | Счета, кредиты, платежи | Банковская лицензия, требования ЦБ, свой стек (Go/Java) |
| Корпоративный | Персонал, инвентаризация, финотчётность головного офиса | Общие функции компании, не относятся ни к одному направлению |
| Фарма | Каталог препаратов, остатки, поставки | Новый бизнес, приходит со своими системами |
| Электроника | Телеметрия и обслуживание медоборудования | Новый бизнес, свои данные с устройств |
| Платформа данных | Lakehouse, витрины, портал, каталог | Не бизнес-домен: общая инфраструктура, витрины на ней строят домены |

Клиент - общий идентификатор `client_id` во всех доменах. Профиль клиента у каждого домена свой: медицинский в клиниках, финансовый в финтехе.

## Сценарии на DFD

1) **S1 - новый финтех-сервис (рассрочка на лечение).** Клиники публикуют событие «счёт на лечение» без диагнозов, финтех на него подписывается. DWH и клиники не дорабатываются.
2) **S2 - ИИ-анализ медданных.** Медданные идут по отдельному контуру: БД клиник → Kafka медданных → ИИ. Рекомендации возвращаются врачу по запросу.
3) **S3 - отчётность.** Домены публикуют данные через CDC, платформа строит витрины, сотрудник получает отчёты в портале.
4) **S4 - фарма и электроника.** Подключаются по тому же шаблону: своя БД → Kafka. Фарма получает агрегированный спрос на препараты, клиники - наличие препаратов.

## Выгода для бизнеса

1) **Быстрее вывод продуктов.** Новый сервис подписывается на готовые контракты доменов, без очереди в команду DWH.
2) **Нет зависимости от DWH.** Логика живёт в доменах, хранилище только для аналитики. Отказ платформы не останавливает клиники и финтех.
3) **Независимое развитие.** Каждый домен релизится и масштабируется сам, меняет схему своей БД без согласования с остальными.
4) **Соответствие регуляторам.** Медданные и банковские данные разделены физически, доступ ограничен владельцем домена.
5) **Новый бизнес без перестройки.** Фарма и электроника подключаются по шаблону, а не через доработку общей системы.
