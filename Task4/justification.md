# Обоснование конфигурации

## Что разворачивается

1) VPC и подсеть.
2) ВМ с публичным IP через NAT — для тестирования и развёртывания сервиса.
3) Загрузочный диск и отдельный диск данных.
4) Security group: снаружи открыт только SSH.

Вручную: облако и каталог (промокод), сервисный аккаунт с авторизованным ключом, SSH-ключ. Это секреты и права доступа — их не создают тем же кодом, которому они выдают права. Ключ `key.json` в `.gitignore`.

Сервисный аккаунт вместо OAuth-токена: OAuth-токены, выпущенные после 01.06.2026, Yandex Cloud больше не обменивает на IAM-токены. Кроме того, у сервисного аккаунта права только на один каталог.

## Ресурсы и параметры

| Ресурс | Параметры | Почему |
|---|---|---|
| ВМ | 2 vCPU 20%, 2 ГБ | Тестовая среда, хватает для одного сервиса. В проде — 100% vCPU и больше памяти |
| Загрузочный диск | HDD 10 ГБ | ОС и пакеты, скорость не критична. Укладывается в квоты учебного облака |
| Диск данных | SSD 10 ГБ, отдельный | Данные отдельно от ВМ: ВМ можно пересоздать без потери данных. SSD — под нагрузку БД |
| Прерываемая ВМ | `preemptible = true` | В несколько раз дешевле для тестовой среды. В проде выключается одной переменной |
| NAT | `nat = true` на интерфейсе | Публичный IP для доступа по SSH и выход в интернет за обновлениями и пакетами |
| Security group | Входящий только TCP 22 | Минимальная поверхность атаки. Адреса для SSH задаются переменной |

## Почему декларативный подход

1) Описываем целевое состояние, а не шаги. Terraform сам вычисляет разницу и порядок создания по зависимостям.
2) `plan` показывает изменения до применения — их можно проверить на ревью.
3) Повторный `apply` без изменений ничего не делает. Ручные правки в консоли видны как расхождение.

## Как IaC помогает воспроизводимости и масштабированию

1) **Воспроизводимость.** Окружение создаётся одинаково из кода в git. Dev, test и prod отличаются только `terraform.tfvars`.
2) **Масштабирование.** Новый домен (фарма, электроника) получает такую же среду с другим `prefix`, без ручной настройки.
3) **Аудит.** Каждое изменение инфраструктуры — коммит и пул-реквест. Это важно для регуляторов.
4) **Восстановление.** Потерянное окружение пересоздаётся одной командой.
