## Перенос функций ESB

Kafka только доставляет сообщения. Обработка, которая сейчас живёт в маршрутах Camel, переезжает в домены.

| Функция ESB                     | Куда переезжает                                                                           | Ответственный                       |
|---------------------------------|-------------------------------------------------------------------------------------------|-------------------------------------|
| ФЛК (формат, обязательные поля) | Schema Registry: событие не по схеме не публикуется. Контракт проверяется в CI            | Домен-производитель                 |
| ФЛК (бизнес-правила)            | Сервис-потребитель до обработки события                                                   | Домен-потребитель                   |
| Потоковые преобразования        | Слой адаптации (ACL) в сервисе-потребителе                                                | Домен-потребитель                   |
| Пакетные преобразования         | DAG'и Airflow                                                                             | Домен - владелец витрины            |
| Бизнес-логика маршрутов         | Сервисы доменов                                                                           | Домен - владелец сценария           |
| Ошибки и повторы                | Retry-топики с задержкой, DLQ, алерт на DLQ и consumer lag. Идемпотентность по ID события | Потребитель, мониторинг - платформа |
| Гарантия доставки               | Transactional outbox для бизнес-событий (платёж, счёт). CDC - для аналитики               | Домен-производитель                 |

Приёмка до переключения маршрута:
1) Инвентаризация маршрутов Camel: что проверяет, преобразует, куда повторяет.
2) Параллельная работа ESB и Kafka, сверка результатов.
3) Сквозные сценарии пройдены: оплата лечения, рассрочка, кредит, рекомендация ИИ, отчётность ЦБ.
4) Переключение по одному маршруту, откат на ESB до приёмки.


## Приоритизация (MoSCoW)

Must:
1) №1 - без доменов не решается остальное.
2) №3 - регуляторный риск, блокирует облако.
3) №2 - главная боль бизнеса.
4) №4 - без него нет портала.

Should:
1) №6 - без каталога нет самообслуживания.
2) №5, №7 - снимаются вместе с №1.
3) №8 - легаси допускается временно.

Could:
1) №9 - решается переездом в облако.
2) №10 - шина живёт для легаси-интеграций.

Won't (в этом году):
1) Полный отказ от легаси - риск для медицинских и финансовых сервисов.
