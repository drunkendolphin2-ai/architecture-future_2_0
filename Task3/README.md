# Задание 3

## Техрадар

Проект: `tech_radar/` (AOE Technology Radar). Скриншот: `techradar.png`.

Запуск:
```
cd tech_radar
npm install
npm run build
npm run serve
```

Две версии:
1) `radar/2026-10-01` — текущее состояние.
2) `radar/2026-10-31` — целевое. Легаси в «Выкидываем», новые технологии в остальных кольцах.

У каждой технологии в карточке указаны поддерживаемые бизнес-сценарии.

| Кольцо | Технологии |
|---|---|
| Активно используем | Data Mesh, DDD, IaC, техрадар, Yandex Cloud, Kubernetes, PostgreSQL, Kafka, ClickHouse, Debezium, Airflow, Terraform, Keycloak, Go, Java, Python |
| Пробуем | S3 + Iceberg, Nessie, DataHub, DataLens, контракты данных в CI |
| Изучаем | Trino, PyIceberg / Spark |
| Выкидываем | SQL Server 2008, PowerBuilder, Power BI, ESB на Camel, бизнес-логика в DWH |

## Роадмап

| Этап | Сроки | Результат | Команды | Ресурсы | Бизнес-цель |
|---|---|---|---|---|---|
| 1. Архитектура и домены | мес. 1–2 | Решение согласовано, границы и владельцы доменов, контракты данных | Архитекторы, владельцы доменов | 2 архитектора, product owner на домен | Промежуточное состояние |
| 2. Облачная основа | мес. 2–4 | Yandex Cloud, сети и каталоги по доменам, Terraform, Keycloak, Kafka | Платформа, ИБ | 3 DevOps, 1 ИБ | Масштабирование, требования регуляторов |
| 3. Платформа данных MVP | мес. 3–6 | Lakehouse, Airflow, ClickHouse. CDC финтеха и корпоративного домена. Пилот портала на финотчётности | Платформа данных | 4 дата-инженера, 1 аналитик | Быстрая отчётность |
| 4. Выделение клиник | мес. 4–8 | Медданные в PostgreSQL клиник, новый интерфейс вместо PowerBuilder, Kafka медданных, ИИ на новом контуре | Клиники, ИИ, ИБ | 6 разработчиков, 2 QA, 1 ИБ | Качество медсервисов, изоляция медданных |
| 5. Самообслуживание | мес. 6–10 | DataHub, витрины всех доменов, ролевой доступ, обучение пользователей | Платформа данных, аналитики доменов | 2 дата-инженера, аналитик на домен | Портал самообслуживания |
| 6. Вывод легаси | мес. 8–12 | Отчёты из Power BI в портале, SQL Server в архиве только для чтения, ESB только для легаси. Шаблон подключения нового домена | Все домены, платформа | Время команд доменов | Снижение затрат, подключение фармы и электроники |

Сквозные меры для медицинских и финансовых сервисов:
1) Параллельная работа старого и нового интерфейса клиник до приёмки.
2) Сверка данных SQL Server и новых БД на каждом шаге миграции.
3) Резервирование и геораспределение БД клиник и финтеха с этапа 2.

## Обоснование

1) **Архитектура и домены.** Без границ и владельцев каждая команда снова пойдёт дорабатывать DWH. Дешёвый этап, снимает риск переделок.
2) **Облачная основа.** Без сетей, IAM и Kafka нельзя изолировать медданные и запускать домены. Снижает затраты на железо, даёт масштабирование.
3) **Платформа данных MVP.** Первый видимый результат для бизнеса: отчёты за секунды вместо часов. Начинаем с финтеха и корпоративного домена — там нет медданных, риск минимальный.
4) **Выделение клиник.** Самый рискованный этап, поэтому после того, как платформа обкатана. Снимает регуляторный риск и единую точку отказа.
5) **Самообслуживание.** Сотрудники строят отчёты сами, без очереди к аналитикам. Ускоряет управленческие решения.
6) **Вывод легаси.** Снимает затраты на поддержку и риски ИБ. Новые бизнесы подключаются по шаблону, без доработки DWH.
